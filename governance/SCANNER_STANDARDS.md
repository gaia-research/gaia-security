# Scanner standards
- **CodeQL**: preserve GitHub default setup in the initial targets (actions, JavaScript/TypeScript, Python; default suite; remote threat model). Advanced setup is an explicit reviewed migration, never a device for hiding fixture noise. Verify recent analyses separately from configuration. The CLI ingests open alerts; it does not run CodeQL locally.
- **Semgrep CE**: pinned open-source native binary and versioned local profile. Disable metrics/version checks. This baseline uses a small reviewable pattern set, not cloud/Pro rules. Missing binary means NOT executed; no homemade detector substitutes for it. Native semantic validation and safe rule fixtures are required before claiming rule coverage.
- **Trivy**: pinned open-source binary, central config. This foundation adapter covers filesystem misconfiguration only; OSV complements dependency scanning. It does not claim image/OS/container vulnerability coverage. Scan fixtures and generated/bundled source; exclude only dependency caches and .git.
- **Gitleaks**: central default-rule extension, no blanket fixture, lockfile or disposition allowlists. Working-tree scan with redacted report and private temporary storage; history coverage requires a separately authorized native git scan. Never add a live credential to an allowlist.
- **OSV-Scanner**: pinned v2 CLI, central empty-suppression config, open advisory data; network required for database queries. Minimum version constraints are not proof of an installed vulnerable version. Match package, advisory aliases and manifest when deduplicating.
- **Dependabot**: ingest open native alerts separately from automatic update settings. The template groups updates and limits PR volume; adoption is PR-reviewed and does not turn on repository features. No new target config is installed in this mission.
- **Native guards**: preserve Skill Tree securityScanner, DOM checks and historical credential-disposition integrity; preserve Skill Heaven SDK URI-template build patch and reproducible bundles. Zero declared dependencies does not mean bundled third-party code is absent.

JSON-formatted .yml profiles are valid YAML 1.2 and parse with the standard library. validate-configs checks syntax/baseline invariants, not native rule semantics. Tool exit failure or partial parse is never “clean”. Suppressions require explicit reviewer evidence/expiry, not automatic path guesses.
