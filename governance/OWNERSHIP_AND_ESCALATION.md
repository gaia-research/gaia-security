# Ownership and escalation
Founder/security authority: @mbtiongson1. Existing repository CODEOWNERS and maintainers remain authoritative for reviews. Verifiers assist investigation but do not gain settings or merge authority through a scanner packet.

Escalate suspected active compromise immediately through the private intake in SECURITY.md; preserve minimum evidence without copying credentials. Uncertain reachability, disputed disposition, ownership gaps or policy exceptions go to the founder.

Steward Class A remains limited to its existing deterministic repair allowlist. Class B proposes bounded agent repairs; “the machine may reject or escalate; the machine may never accept.” Class C escalates governance exceptions to the founder. Security scanning does not widen these classes or reactivate locked workflows.

Approval gates: detection -> independent security validation -> explicit repair authorization -> repository tests and review -> founder-authorized merge/release. Never merge or deploy as part of a scan. One compatible integration PR per affected repository/run; preserve each repository's merge rules.
